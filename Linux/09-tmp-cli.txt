= Temporary file
/tmp -> Linux's temporary workspace
/tmp is a directory used by Linux programs and users to store temporary files that are needed for a short period of time.


Note:
Be careful about relying on files in /tmp permanently. Temporary directories can be cleaned automatically.


eg:
  /tmp/app.tmp
  /tmp/download.tmp
  /tmp/session123
  /tmp/cache-file
  /tmp/build-12345

Different applications use different naming conventions.
Don't assume every file has a .tmp extension.
The temporary file doesn't need to permanently remain on the system.
A temporary file can have any name.

= Why does /tmp exist?
Programs frequently need temporary storage.


------------------------------------------------
= /tmp vs /var/tmp

| Directory  | Purpose                         | Expected lifetime  |
| ---------- | ------------------------------- | ------------------ |
| `/tmp`     | Temporary files                 | Short-lived        |
| `/var/tmp` | More persistent temporary files | Can survive reboot |


/tmp
Used for temporary data that doesn't need to survive a reboot.

/var/tmp
Used for temporary data that may need to remain available after reboot.

Think:
/tmp
   ↓
"I need this temporarily."

/var/tmp
   ↓
"I need this temporarily,
 but it may need to survive reboot."


------------------------------------------------
= Does /tmp get deleted automatically?
Potentially, yes.
The exact cleanup mechanism depends on the Linux distribution and configuration.
Many modern Linux systems use systemd-tmpfiles to clean temporary files.

------------------------------------------------
= Important: Don't use /tmp for permanent data
Suppose you have an important application configuration: /tmp/my-app-config.conf
That's generally a bad place for permanent configuration.
Why?
Because /tmp is intended for temporary data and files may be cleaned up.

Instead, depending on what you're storing, you might use: /etc
for system configuration: /var/lib
for persistent application data or user data: /home/


Think:
Temporary
    ↓
/tmp

Configuration
    ↓
/etc

Persistent application state
    ↓
/var/lib

User files
    ↓
/home

------------------------------------------------
= Permissions of /tmp
ls -ld /tmp // output = drwxrwxrwt 10 root root 4096 Sep 30 15:00 /tmp

Pay special attention to:
                            drwxrwxrwt
                                    ↑
                                    t
The final t is called the sticky bit.



= What is the sticky bit?
The sticky bit provides an important security behavior for shared directories.
Normally /tmp is writable by many users.
  "If everybody can write there, can one user delete another user's temporary files?"
The sticky bit helps prevent that.

eg:
/tmp
│
├── userA-file
├── userB-file
└── userC-file

User A shouldn't normally be able to delete User B's file simply because /tmp is writable.
The sticky bit restricts deletion/renaming so that it is generally allowed only to:
                                                                                    the file owner
                                                                                    the directory owner
                                                                                    root
That's why /tmp commonly has: drwxrwxrwt
instead of simply: drwxrwxrwx





= Understanding the /tmp permissions
d rwx rwx rw t
│ │   │   │ │
│ │   │   │ └── sticky bit
│ │   │   └──── others
│ │   └──────── group
│ └──────────── owner
└────────────── directory


More conventionally:
                  d rwx rwx rwx
                            ↑
                            becomes t
means:
Owner:   rwx
Group:   rwx
Others:  rwx
Sticky:  enabled

------------------------------------------------
= Creating a temporary file
touch /tmp/test.txt
ls -l /tmp/test.txt   // output = -rw-r--r-- 1 user user 0 Sep 30 15:30 /tmp/test.txt
echo "Hello Linux" > /tmp/test.txt
cat /tmp/test.txt
rm /tmp/test.txt

------------------------------------------------
= Creating a temporary directory
mkdir /tmp/myapp
cd /tmp/myapp
touch file1
touch file2
ls
cd /
rm -rf /tmp/myapp

------------------------------------------------
= creates a unique temporary file
For file:
mktemp      // output = /tmp/tmp.X7k3pQ9a

This is much safer than manually creating something like: /tmp/test.txt
because multiple processes could accidentally choose the same filename.



for directory:
mktemp -d        // output = /tmp/tmp.8JkLmP2x
cd /tmp/tmp.8JkLmP2x


This is very useful in shell scripts.
eg:
TEMP_DIR=$(mktemp -d)
echo "Working in $TEMP_DIR"
# Do temporary work here
rm -rf "$TEMP_DIR"

= /tmp and applications

eg in CI/CD pipeline:
Git repository
       ↓
CI runner
       ↓
Download source
       ↓
/tmp/build-123/
       ↓
npm install
       ↓
npm test
       ↓
Build
       ↓
Artifact
       ↓
Cleanup


Temporary build files don't necessarily need to remain permanently.
So /tmp can be useful for intermediate work.
------------------------------------------------
= /tmp and Docker
docker exec -it mycontainer sh
ls -la /tmp

You may find temporary files created by applications running inside the container.

eg:
Container
│
├── /app
├── /etc
├── /var
├── /tmp
└── /usr

/tmp inside a container belongs to the container's filesystem unless you explicitly mount something there.

------------------------------------------------
= /tmp and security
/tmp is an interesting security area because many users and applications may interact with it. 
Potential problems include: Predictable filenames
Bad: /tmp/myapp.txt
A malicious process could potentially interfere with predictable temporary filenames.
Better: mktemp
which generates a unique name.

= Incorrect permissions
A program shouldn't blindly create sensitive information in a world-readable temporary file.
eg: /tmp/password.txt
would be a terrible design if it contains sensitive information and has permissive permissions.
Applications should use appropriate permissions and secure temporary-file APIs.

------------------------------------------------
= /tmp and RAM — an important misconception
You may hear: "/tmp is RAM."
That's not universally true.
On some Linux systems, /tmp may be mounted as: tmpfs
which uses memory and potentially swap.
But on other systems /tmp can simply be part of a disk-backed filesystem.

= Check
df -h /tmp

Output:
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           7.8G  1.2M  7.8G   1% /tmp

If you see: tmpfs
then /tmp is using a memory-backed filesystem.
But don't assume that every Linux system uses tmpfs for /tmp.
